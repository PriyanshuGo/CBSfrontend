AUTHENTICATION FLOW
================================================================================

1. Login Process:
   - User enters email/password on /login page
   - Credentials sent via useLoginMutation hook to POST /login
   - API returns { accessToken, user: { role: { name: "principal|teacher" }, ... } }
   - Token stored in localStorage via setAccessToken()
   - User data stored in localStorage as JSON
   - Redux auth state updated via setCredentials() action:
     * state.user = user object
     * state.accessToken = token
     * state.isAuthenticated = true
   - Conditional redirect based on user role:
     * role === "principal" → /principal/dashboard
     * role === "teacher" → /teacher/dashboard

2. Token Management:
   - Access token stored in localStorage
   - Token utilities in src/utils/token.js:
     * getAccessToken() - retrieves token from localStorage
     * setAccessToken(token) - saves token to localStorage
     * removeAccessToken() - clears token from localStorage
   - Token automatically added to all authenticated API requests via axios interceptor

3. Session Persistence:
   - Token persists in localStorage across page reloads
   - User data loaded from localStorage in navbar on mount
   - Redux state lost on page reload (relies on localStorage for persistence)

4. Logout Process:
   - User clicks logout in navbar dropdown
   - logoutApi() mutation called (POST /logout with token)
   - removeAccessToken() clears token from localStorage
   - localStorage.removeItem("user") clears user data
   - Redux logout action resets auth state
   - Browser redirected to /live (public page)

5. Authentication State Source:
   - Primary: Redux state (auth slice)
   - Fallback: localStorage (for SSR/page reloads)
   - Navbar checks both: isAuthenticated from Redux || mountedUser from localStorage


ROLE-BASED ROUTING
================================================================================

1. User Roles:
   - principal: School/institution administrator
   - teacher: Content creator/uploader
   - live: Public user (no authentication required)

2. Route Structure:
   - /live              → Public (everyone can access)
   - /login             → Public (unauthenticated only)
   - /principal/*       → Principal-only dashboard
   - /teacher/*         → Teacher-only dashboard

3. Implementation:
   - No middleware protection currently implemented
   - Role-based redirect happens AFTER login based on user.role.name
   - Dashboard pages should implement role checks on load
   - Protected routes rely on user being logged in to localStorage/Redux

4. Route Hierarchy:
   - Home (/) redirects to /live
   - /live/page.jsx displays live content
   - /login/page.jsx shows login form
   - Role-specific dashboards branch from there

5. Recommended Protections (NOT YET IMPLEMENTED):
   - Should implement route guards in middleware
   - Verify user role before rendering protected pages
   - Redirect unauthorized access back to login


API INTEGRATION APPROACH
================================================================================

1. Technology Stack:
   - Redux Toolkit Query (RTK Query) - caching, synchronization
   - Axios - HTTP client with interceptors
   - Custom baseQuery for RTK Query using Axios

2. API Architecture:
   apiSlice (src/services/api/apiSlice.js):
   - Creates RTK Query API object
   - baseQuery: custom axios-based query function
   - tagTypes: ["Auth", "Content", "Approval", "LiveContent"]
   - endpoints: extended by feature-specific API files

   Feature APIs (injectEndpoints):
   - authApi.js: login, logout mutations
   - contentApi.js: content CRUD operations
   - approvalApi.js: content approval workflows
   - liveApi.js: live streaming queries

3. Axios Configuration (axiosInstance.js):
   - Two instances:
     * publicAxios: no authentication (login endpoint)
     * privateAxios: includes Bearer token in Authorization header

   - Base URL from env: NEXT_PUBLIC_API_BASE_URL
   - Credentials: withCredentials=true (for cookies)

4. Interceptors:
   - Request interceptor (FormData handling):
     * Removes Content-Type header for FormData
     * Allows browser to set proper multipart/form-data boundary

   - Request interceptor (privateAxios):
     * Adds Authorization: Bearer {token} header
     * Retrieves token from localStorage via getAccessToken()

   - Response interceptor (private only, line 46+):
     * Likely handles token refresh/expiry
     * File truncated - check full axiosInstance.js

5. API Query Pattern (RTK Query):
   useLoginMutation() - returns [mutate, { isLoading }]
   Example:
   ```
   const [login, { isLoading }] = useLoginMutation();
   const response = await login(credentials).unwrap();
   ```

6. Error Handling:
   - Wrapped in try/catch blocks
   - Error?.data?.message parsed for API error messages
   - Fallback error message: "Login failed"

7. Tag Invalidation (Caching):
   - Tags defined: Auth, Content, Approval, LiveContent
   - After mutations, tags invalidated to refetch affected data
   - Example: login mutation might invalidate "Content" tag to refresh user's content


STATE MANAGEMENT APPROACH
================================================================================

1. Architecture: Redux Toolkit + RTK Query

2. Store Setup (src/store/store.js):
   - configureStore() from @reduxjs/toolkit
   - Reducers:
     * auth: authSlice reducer (user, token, isAuthenticated)
     * [apiSlice.reducerPath]: apiSlice reducer (caching)
   - Middleware:
     * Default middleware + apiSlice.middleware (RTK Query)

3. Auth Slice (src/features/auth/authSlice.js):
   State shape:
   {
     auth: {
       user: { id, name, email, role: { name: "principal|teacher" } } | null,
       accessToken: string | null,
       isAuthenticated: boolean
     }
   }

   Reducers:
   - setCredentials: stores user + token, sets isAuthenticated=true
   - logout: clears all auth state

4. API Slice (src/services/api/apiSlice.js):
   - RTK Query API instance
   - Manages request caching & synchronization
   - Endpoints extended dynamically by feature APIs
   - baseQuery: uses custom axios base query

5. Access in Components:
   - useSelector() to read state: const { user, isAuthenticated } = useSelector(state => state.auth)
   - useDispatch() to update: dispatch(setCredentials(...))
   - useLoginMutation() for API calls: const [login, { isLoading }] = useLoginMutation()

6. Persistence Strategy:
   - localStorage used for tokens + user data
   - Redux state rehydrated from localStorage on app load
   - Navbar component loads user from localStorage on mount (useEffect)

7. Data Flow:
   Login Page:
   1. User submits form
   2. useLoginMutation sends request → API
   3. API returns token + user
   4. Component saves token to localStorage
   5. Component dispatches setCredentials() to Redux
   6. Component navigates based on user.role

   Protected Components:
   1. useSelector reads auth state
   2. Conditional rendering based on isAuthenticated
   3. usePrivateApi() hooks automatically include token via interceptor

8. Caching Strategy (RTK Query):
   - tagTypes: Auth, Content, Approval, LiveContent
   - Automatic refetch on tag invalidation
   - Example: Creating content invalidates "Content" tag
   - All users accessing that tag refetch immediately
